# Build an adapter

Start with `examples/hello.ts`. Import `serve`, `credential`, `AdapterError` and
the inferred types from `src/index.ts`. Each handler receives its typed request
and returns its typed result. `serve` validates both at runtime with Zod.

Run `bun install --frozen-lockfile`, then `bun run check`. Try the complete wire
flow without Ryra or a credential:

```sh
printf '%s\n' '{"version":1,"request":{"operation":"files.list","location":{"kind":"root"},"next":null}}' | bun --no-install examples/hello.ts
```

An executable handles one JSON request on stdin and writes one JSON response to
stdout, then exits. Version 1 supports `files.list`, `files.download` and
`directory.read`. Other languages can use `input.schema.json` and
`response.schema.json`, generated by `bun run schema`. No daemon or MCP SDK is
required. An existing tool can be wrapped to return these rows.

Declare a service with optional authentication:

```nix
{
  meta = {
    summary = "Example files";
    auth.example = {
      label = "Example account";
      why = "Read your files";
      connect = {
        kind = "token";
        page = "https://example.com/settings/tokens";
        scopes = "Read files";
        fields = [ "token" ];
      };
      environment.EXAMPLE_TOKEN = "token";
    };
    adapters.example-files = {
      label = "Example files";
      command = [ "ryra-adapter-example" ];
      connection = "example";
      files = { start = "root"; hint = "Browse your files"; };
    };
  };
}
```

For a public adapter, omit both `auth` and `connection`. `connection` names an
entry in the same index's `meta.auth`. Ryra supplies only
that connection's declared environment fields, refreshes OAuth access first,
and keeps refresh credentials out of the adapter. API keys use the same field
bindings. Read them with `credential("EXAMPLE_TOKEN")`; never log them. Installed
executables are trusted code running as their operating-system user, not a
sandbox. Long-running services use a separately reviewed service credential and
private refresh state with `ryra integrations run --credentials ... --state ...`.

Return rows, not markup. Pagination stays opaque to Ryra. Validate provider data
with Zod, restrict authenticated requests and continuation URLs to the provider,
and never forward authorization to a download redirect. Throw `AdapterError`
with a declared code, never a provider response body. Stdout is reserved for the
protocol. Requests are limited to 64 KiB, results to 36 MiB, downloads to 25 MiB,
and execution to 120 seconds. Download data is base64, never a local path.

Keep provider registration, endpoints, scopes and API mappings beside the
service. Ship the adapter with its runtime and dependencies pinned by Nix.
Ryra uses an installed executable or builds the declared package on first use;
Bun never installs dependencies during login. A custom
repository can use `ryra-services.lib.mkAdapter { inherit pkgs; name = "example";
src = ./adapter; }`, with `adapter.ts` in that directory. That package exposes
`ryra-adapter-example` and resolves `import { serve } from "@ryra/adapter"`.
Use a local file dependency on this SDK for development; its `exports` supplies
the types. `lib.withServices` includes every selected service's `package` and
sets the same index for discovery and authentication.

For automatic installation, export `packages.<system>.<name>` and include
`package = "name"` in the service's index metadata. This repository derives both
from each service's `package = pkgs: ...` function. Authentication and tool IDs
in an additional repository are qualified as `namespace.id` by Ryra. Inside the
repository, use local IDs for adapter connections and personal credential links.

## Authentication adapters

Start from `services/gh/adapter.ts` or `services/resend/adapter.ts`. Import
`serveAuth`, `authorize`, `openBrowser`, `post`, `Authorization` and
`AuthHandlers` from `@ryra/adapter/auth`. Zod infers the handlers and validates
their input and output. `auth-input.schema.json` and `auth-event.schema.json`
describe the same contract for other languages.

Add this beside a token definition's `connect` and `environment`:

```nix
driver = {
  command = [ "ryra-adapter-example" ];
  configuration.client_id = "public-registration-id";
  required = [ "client_id" ];
};
```

`serveAuth({ login, refresh })` receives either `auth.login` with configuration
or `auth.refresh` with the last opaque state. Each handler returns
`{ fields, state, expires_at }`. `fields` must exactly match the declared token
fields. `expires_at` is Unix seconds, or `null` for credentials without expiry.
Verify identity and permissions with a real authenticated read before returning.
Refresh must preserve that identity and refuse broader permissions.

`authorize` runs a loopback callback with PKCE and state checks and opens one
browser URL. `openBrowser` also supports hosted authorization or a device flow's
complete verification URL. A flow requiring a separate user code must provide
its own browser page or existing tool. Client-credentials, signed requests,
service accounts and certificates stay in the adapter. It owns protocol details
and how initial private credentials are obtained; private values never go in Nix.

Authentication uses one stdin request and newline-delimited JSON events on
stdout: optional `open` and `progress`, then `connected` or `error`, then exit.
`progress("waiting")` and `progress("verifying")` update the login status;
`authorize` sends these around its callback and account selection automatically.
Ryra requires a
successful exit before saving. Output and input are bounded to 1 MiB; login has
300 seconds and refresh 60 seconds. The initial response must arrive within
30 seconds. Cancellation stops preparation or the running process. It does not
revoke provider consent or remove packages already cached by Nix.

Ryra encrypts `state` with the connection, runs refresh before use and persists
the replacement before starting a consumer. A reviewed service binding reuses
the same adapter with private persistent state after restart. Consumers receive
only the definition's environment fields, never the opaque state. These are
credential boundaries, not an OS sandbox around trusted adapter executables.

From the repository root, the provider regression check is:

```sh
rustc --edition=2021 --test adapters/tests.rs -o /tmp/ryra-adapter-tests
/tmp/ryra-adapter-tests
```

It exercises Bun against an HTTP fixture, including pagination, document export,
download redirects, login callbacks, grant checks and credential refresh.
