# Nextcloud

Shared files, calendars and contacts hosted on your organization's machines.

Ryra configures the database, backups and private access when you install it. Choose a public domain to enable automatic HTTPS. Each machine gets a separate installation with its own Nextcloud accounts. See [operational notes](SKILL.md).

Enabling `ryra.services.auth.provider` selects shared OIDC login for compatible hosted applications. Supply their runtime files through `provider.clientSecrets.<name>.clientSecretFile` and `secretHashFile`; explicit `auth.mode = "none"` opts out. Private applications require `web.externalUrl`, a stable HTTPS origin supplied by the machine's access route. Nextcloud inherits the NixOS package default, installs its matching `user_oidc` package and reconciles the Ryra provider after setup. DAV and mobile clients keep using Nextcloud's own app passwords.

The provider module is exported as `nixosModules.auth-authelia-lldap`. It accepts runtime secret paths, issuer and directory settings, instance and storage paths, and `extraClients` for applications such as Grafana. Directory bootstrap, access rules, notifier and HTTPS routes belong to the machine configuration. Reuse `lib.checkAuth { config = evaluated.config; lib = nixpkgs.lib; }` before deployment. `bash scripts/auth-smoke.sh ISSUER APP_URL nextcloud CREDENTIALS_JSON EXPECTED_USER` verifies an actual login; use `linkding` to verify that application's authenticated session. The protected runtime JSON file contains `username` and `password`. Run this with a one-factor test identity whose consent is already granted or explicitly implicit. The script deletes its temporary cookies and credential copies. `auth-runtime-check.sh` checks Linkding's evaluated credential script for interrupted-write recovery and empty-secret refusal.

`lib.authLiveTest { issuerUrl = ...; nextcloudUrl = ...; linkdingUrl = ...; cookieDomain = ...; }` supplies both applications and a provider for a disposable guest. It accepts `credentialDirectory` (default `/run/ryra-auth-test`), optional `credentialsReadyUnit` and `directoryBootstrapUnit`. The guest supplies runtime credentials, directory users and HTTPS routes; the fixture uses a filesystem notifier. For a fresh guest, use `system.stateVersion = "26.05"` so the native package default selects Nextcloud33 on the tested pins.

The live smoke uses its test user's native login-v2 app password for WebDAV, CalDAV and CardDAV, writes and deletes a unique file, then revokes that password. The Linkding branch creates a native API token and bookmark canary and removes both. Credential material stays in protected scratch files. Linkding's preferences API does not expose identity; verify its account id and email in the service database across repeated login and restarts.
